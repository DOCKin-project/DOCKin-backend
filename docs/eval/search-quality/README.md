## 정답 조건

질문마다 `equipment`·`unit`·`part`·`symptom`·`cause`·`action` 칸에 조건을 적었다. 빈 칸은 조건이 아니다.
정답 집합은 하네스가 **한국어 원문(`source_type = 'WORK_LOG'`)** 에 SQL로 매번 계산한다. 원문 첫 문장의 틀이 고정이라 그 틀로 맞춘다.

```
{설비} {호기}호기 {부품}에서 {증상}.  점검 결과 {원인} …  {조치}.
```

| 조건 | 매칭 |
|---|---|
| 설비+부품(+증상) | `content LIKE '%{설비} %호기 {부품}에서 {증상}%'` — 긴 본문의 두 번째 쌍(`part2`·`symptom2`)도 같은 틀이라 같이 걸린다 |
| 설비+호기+부품 | `content LIKE '%{설비} {호기}호기 {부품}%'` |
| 설비+원인/조치 | `content LIKE '{설비}%' AND content LIKE '%{원인}%'` |

부품과 증상을 따로 LIKE로 걸지 않는 이유: 긴 본문은 (부품1, 증상1)과 (부품2, 증상2)를 함께 담아서, 따로 걸면 부품1과 증상2가 섞인 일지를 정답으로 센다.

### 정답 수 예상

2만 건 안팎에서 조건 조합마다 평균 몇 건이 정답인지다. 0건이 나온 질문은 하네스가 따로 보고하고 집계에서 뺀다.

| 조건 | 조합 수 | 조합당 평균 |
|---|---|---|
| 설비+부품+증상 | 12×10×12 = 1,440 | 십여 건 |
| 설비+호기+부품 | 12×9×10 = 1,080 | 십여 건 |
| 설비+원인 | 12×10 = 120 | 백여 건 — 쉬운 질문이다 |
| 설비+증상+원인 / 설비+원인+조치 | 1,440 | 십여 건 |

호기에 증상까지 붙이면(12,960조합) 조합당 1~2건이라 0건이 흔해서 넣지 않았다.

## N 유형 확인

N은 "정말 답이 없는가"를 하네스가 먼저 확인한다. 핵심 단어(로봇 티칭, 비계, 방독 마스크, 단가, 정격 하중, 운전 자격)가 한국어 원문에 한 번이라도 나오면 그 질문은 N에서 뺀다.
`발주`와 `시운전`은 코퍼스 후속 문장에 실제로 나와서 N 질문에 쓰지 않았다.

# 프로젝트 범위 및 역할 분담

DOCKin은 팀 프로젝트다. `docs/adr/*` 문서와 이 저장소(`DOCKin-backend`)에 담긴 모든 설계/구현 내용은 **본인이 담당한 Spring 백엔드 + DB 설계 범위**에 한정된다. 포폴/이력서/면접에서 이 저장소의 내용을 인용할 때, 담당 범위를 벗어난 내용(FastAPI 쪽 AI 처리)을 본인이 만든 것처럼 서술하지 않기 위해 경계를 명시해둔다.

## 담당 범위 (본인, 이 저장소)

- 인증/인가: JWT 발급/블랙리스트, RBAC(`ADMIN`/`USER`)
- 근태: 출퇴근 체크 동시성 제어(Redis 분산락 + DB 유니크 제약), 근무조별 지각 판정 — `docs/adr/0001`
- DB 스키마 설계 전체(`schema.sql`) 및 쿼리/인덱스 (`docs/adr/0002`의 N+1, LIKE 검색 진단 포함)
- 채팅(WebSocket/STOMP), 작업일지 CRUD, 안전교육 이수 관리 API
- FastAPI 연동 클라이언트 레이어(`ai` 패키지: `fastApiService`, `SttService`) — **FastAPI를 호출하고 응답을 받아 DB에 저장하는 Spring 쪽 코드**. `docs/adr/0002` 2-1의 `Mono.zip` 병렬화 제안 등, 이 레이어의 성능/구조 개선은 본인 책임 범위.

## 팀원 담당 범위 (다른 저장소, 본인 책임 아님)

- FastAPI 서버: HuggingFace 기반 번역, STT(음성 인식). **임베딩/벡터 검색은 없음.**
- (프론트엔드 등 있다면 별도 담당자 — 필요 시 추가)

## 명시적으로 짚어야 할 오해 소지

- `docs/adr/0003`(검색 도메인 확장)은 Spring 쪽 검색 쿼리(`Work_logsRepository.searchWorkLogs`, 현재 LIKE 방식)에 대한 **로드맵**이지, 이미 구현된 하이브리드 벡터검색이 아니다. FastAPI가 번역/STT만 수행하므로 벡터 임베딩 기반 교차언어 검색은 이 프로젝트에 존재하지 않는다 — 만약 향후 이 소재를 포폴에 쓴다면 "설계했다"가 아니라 "로드맵으로 검토했다"로만 서술한다(0003 원문 표현 그대로).
- "다국어 번역/STT를 구현했다"는 표현은 팀원 담당 영역이므로 쓰지 않는다. 본인 기여는 "번역/STT 결과를 받아 저장·조회·검색 가능하게 만든 백엔드 설계"로 한정해서 서술한다.

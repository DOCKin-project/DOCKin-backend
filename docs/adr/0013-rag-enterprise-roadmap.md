# ADR-0013: 조선소에서 쓸 수 있는 RAG — 기준을 먼저 정하고, 끝까지 한 번 돌린 뒤, 검색과 운영을 채운다

- 상태: **제안, 1단계 측정 완료(2026-11-26, 7절).** 방향(목표 범위·LLM 순서·1단계 범위·문서 위치)은 사용자 결정, 숫자는 초안
- 대상 코드: `rag/service/RagChatService`(`augment`·`buildPrompt`·`extractQuestion`), `rag/service/RetrievalService`, `rag/generation/*`, `ai/quota/AiQuota`, pylab `aiserver/src/aiserver/chatbot.py`
- 관련 문서: ADR-0006(벡터 검색), ADR-0012(구역 공유), `docs/SLO.md` 7-1(검색 품질 기준, PR #194), `docs/SEARCH-QUALITY-EVAL-PLAN.md`(#170), pylab ADR-0004(챗봇 프록시)
- 관련 이슈: #177·#178(프롬프트), #180(HNSW), #197(근거 없음 경로), #198(대화 맥락 검색)
- 작성 목적: 지금까지는 R(검색)을 깊게 팠고 G(생성)는 한 번도 실제 LLM으로 돌지 않았다. 목표를 **"조선소가 업무에 쓸 수 있는 RAG"** 로 정하면 무엇이 모자란지, 어떤 순서로 채울지를 정한다.

## 1. 지금 어디까지 왔나

| 단계 | 진행 | 된 것 | 빈 것 |
|---|---|---|---|
| **R 검색** | 약 70% | 벡터 검색(pgvector), 권한 선필터, 베트남어 번역본 색인, 권한 걸린 키워드 폴백(#188), `iterative_scan`(#191)·`ef_search`(#196), 검색 품질 파일럿과 기준(SLO 7-1) | 품질 미달(영어 Hit@5 0.40, 한국어 의미형 0.47, P@5 0.17~0.58), 평가셋 30문항뿐 |
| **A 프롬프트 조립** | 약 50% | 근거 5개 + "모르면 모른다고" 지시 + 출처 번호 요청, 응답에 근거 목록 | 지시·근거 분리(#181), 답변 언어(#182), 근거 없음 경로(#197), 대화 맥락 검색(#198) |
| **G 생성** | 약 20% | 스텁 생성기, 팀원과 같은 계약의 pylab 프록시(`base_url`로 제공자 교체) | **실제 LLM으로 끝까지 돈 적이 없다.** 답변 품질을 잰 적이 없다 |

출발점: 2026-02 팀 원본에는 RAG가 없었다. 챗봇은 질문을 그대로 OpenAI에 넘겼다. R과 A는 2026-08-04부터 이 저장소에서 새로 만들었다.

## 2. "조선소가 쓸 수 있다"의 조건

데모와 업무 도구는 실패했을 때의 비용이 다르다. 데모는 그럴듯하면 되고, 업무 도구는 **틀린 답이 사람을 다치게 할 수 있다.** 조선소의 질문에는 정비 이력뿐 아니라 위험 작업 절차가 섞인다. 그래서 조건을 여섯 갈래로 나눈다.

| # | 조건 | 왜 조선소에서 | 지금 |
|---|---|---|---|
| C1 | **틀린 답보다 "모른다"가 낫다** — 답의 모든 주장이 근거에 있어야 한다 | 위험 작업 절차를 지어내면 사고로 이어진다 | ❌ 근거 없음 경로가 막혀 있다(#197), 답변 충실도를 잰 적 없다 |
| C2 | **출처를 항상 보여 준다** | 현장 관리자가 답을 원문으로 확인해야 쓴다 | ⚠️ 응답에 근거 목록은 있다. 답변 문장과 출처의 연결은 LLM 지시에만 의존 |
| C3 | **권한 밖 문서가 새지 않는다** — 프롬프트 조작으로도 | 작업일지에는 개인 이력이 있다. 감시로 읽힐 우려가 현장 인터뷰에서 나왔다 | ✅ 선필터, ⚠️ 인젝션(#177, PR #181) |
| C4 | **사내 데이터가 회사 밖으로 나가지 않을 수 있어야 한다** | 조선소는 함정 건조 등 보안 사업이 있어 외부 API 사용이 막힐 수 있다 `[현장 확인 필요]` | ⚠️ pylab이 `base_url`로 자체 호스팅을 받을 수 있지만, 자체 호스팅 모델로 답변 품질을 잰 적 없다 |
| C5 | **세 언어 모두 같은 수준** | 외국인 근로자가 주 사용자다. 한 언어만 덜 맞으면 그 사람들만 위험하다 | ❌ 영어 격차 47~60%p(SLO 7-1) |
| C6 | **운영할 수 있다** — 누가 무엇을 물었고 무엇이 답했는지 남고, 비용에 상한이 있고, 품질이 떨어지면 안다 | 사고가 나면 "챗봇이 뭐라고 했나"를 되짚어야 한다 | ⚠️ `chat_history`에 질문·답·근거가 남는다. 전체 비용 상한 없음, 품질 모니터링 없음 |

**C4가 LLM 선택을 바꾼다.** 외부 API가 막히면 운영 모델은 자체 호스팅이다. 그래서 OpenAI는 **비교 기준**으로만 쓰고, 품질 판정은 운영할 모델로 한다(4절 D2).

## 3. 품질 요구사항 — 검색 기준에 답변 기준을 더한다

SLO 7-1은 R만 본다(Hit@5·P@5·언어 격차). 업무 도구에서는 **검색이 맞아도 답이 틀릴 수 있고**, 그쪽이 더 위험하다. 7-1의 검색 숫자는 그대로 두고 아래를 더한다. 7-1과 같이 **회귀 기준(지금)과 사용자 SLO(파일럿 뒤)** 두 층으로 쓴다.

| SLI | 정의 | 목표 | 근거 |
|---|---|---|---|
| **답변 충실도** | 답의 주장 중 근거 청크에 있는 것의 비율 | **≥ 95%** | C1. 근거 밖 주장 하나가 안전 절차면 사고다 |
| **안전 질문 충실도** | 위험 작업·보호구·절차를 묻는 질문에서 근거 밖 주장이 있는 답의 수 | **0** (불변식) | 이 칸은 비율이 아니라 건수로 본다. 하나라도 나오면 출시를 막는다 |
| **출처 정확도** | 답이 밝힌 출처 번호 중 실제로 그 내용을 담은 근거의 비율 | **≥ 95%** | C2. 출처가 틀리면 확인하러 간 관리자가 다른 문서를 본다 |
| **답 없음 처리** | 답 없는 질문에 "기록을 찾지 못했다"고 답한 비율 | **≥ 90%** | C1. SLO 7-1은 판정 신호가 없어 보류했지만, 업무 도구는 이게 없으면 못 낸다. **출시 조건**으로 올린다 |
| **답변 언어 일치** | 질문 언어로 답한 비율 | **≥ 99%** | C5. 베트남어로 물었는데 한국어로 답하면 못 읽는다(#178) |
| **권한 누출** | 권한 없는 사용자의 답에 남의 일지 내용이 나온 건수 | **0** (불변식) | C3. 선필터 테스트 + 인젝션 테스트로 본다 |
| **응답 시간** | 질문부터 답 완료까지 | **10초 안 ≥ 95%** `[현장 확인 필요]` | 현장에서 장갑 낀 채 기다릴 수 있는 시간. 자체 호스팅 모델의 실측으로 다시 정한다 |

- **"모른다"가 늘어나는 맞바꿈은 받아들인다.** 답 없음 처리를 올리면 답 있는 질문을 거르는 일도 생긴다. 업무 도구에서는 "있는데 못 찾았다"가 "없는 걸 지어냈다"보다 덜 위험하다고 본다. 단, 답 있는 질문의 거부율은 **≤ 10%** 로 위에서 막는다.
- **어떻게 재나:** 평가셋 질문을 실제 LLM으로 돌리고, 답을 LLM 판정기로 채점한다. 판정기를 그대로 믿지 않는다 — 언어마다 30건을 사람이 다시 채점해 판정기와 맞는 비율을 같이 적는다 `[미검증]`.

## 4. 결정

### 1단계 — 끝까지 한 번 돌린다

| # | 결정 | 버린 것 | 이유 |
|---|---|---|---|
| D1 | **G 연결:** Spring `AI_SERVER_URL` → pylab `aiserver`, `ai.chatbot.stub=false` | 팀원 서버에 붙이기 | 둘은 같은 계약이다(pylab ADR-0004). pylab은 `base_url`로 제공자를 바꿀 수 있어 D2를 한 코드로 한다 |
| D2 | **LLM 순서: OpenAI `gpt-4o-mini`로 기준을 만들고, 같은 질문을 자체 호스팅(Ollama, AWS `g4dn.xlarge`, 7~8B 4비트)으로 돌려 비교한다** | 자체 호스팅만 / OpenAI만 | C4 때문에 운영은 자체 호스팅일 수 있다. 그런데 기준 없이 작은 모델만 재면 "모자란 것이 모델 탓인지 검색 탓인지" 가를 수 없다. OpenAI 결과가 상한선 역할을 한다 |
| D3 | **프롬프트를 고친다:** #181(지시는 system, 근거는 `<자료>` 태그)과 #182(답변 언어)를 머지하고, **근거가 없어도 지시를 보낸다**(#197). 근거가 없으면 "기록을 찾지 못했다"고 답하라고 지시한다 | 근거 없음일 때 원본 질문만 넘기기(지금) | C1. 지금은 근거가 비면 LLM이 일반 지식으로 답할 수 있다 |
| D4 | **대화 맥락 검색(#198):** 먼저 앞 user 메시지 최대 2개를 검색어 앞에 붙인다. 이것으로 후속 질문 평가가 모자라면 LLM으로 질의를 다시 쓴다 | 처음부터 LLM 질의 재작성 | 재작성은 호출이 하나 늘고, 자체 호스팅에서는 몇 초가 붙는다. 싼 것부터 잰다 |
| D5 | **답변 평가 하네스:** 파일럿 30문항 × 3언어 + 답 없는 질문 6 × 3언어 + 후속 질문 10쌍을 실제 LLM으로 돌려 3절 지표를 낸다. 원 출력은 `measure/rag-e2e/`에 커밋한다 | 손으로 몇 개 보고 끝내기 | 숫자가 없으면 2단계에서 나아졌는지 알 수 없다 |
| D6 | **키 관리:** `AISERVER_CHAT_API_KEY`는 환경변수로만, 커밋 금지. 측정이 끝나면 키를 폐기한다 | | #195에서 크래시 덤프로 환경 변수가 커밋된 적이 있다 |

**1단계 완료 조건:** 실제 LLM 두 종(OpenAI, 자체 호스팅)으로 D5 세트가 끝까지 돌고, 3절 지표가 두 모델 모두 표로 남는다. 목표를 넘는지는 완료 조건이 아니다 — **어디서 모자란지 아는 것**이 1단계의 산출물이다.

### 2단계 — 검색 품질을 기준까지 올린다

값이 싼 것부터. 각 변경은 SLO 7-1 A의 회귀 기준을 통과해야 머지한다.

1. **평가셋 100문항(E1)** — 회귀 기준의 구간을 좁힌다. 이게 먼저다
2. **영어 번역본 색인** — 베트남어는 번역본으로 0.13 → 0.87. 영어 격차의 가장 싼 해법
3. **하이브리드 검색** — 용어형(호기 번호·약어). 한국어 형태소 분석기가 PostgreSQL 기본에 없어 방법부터 잰다(`pg_trgm` / 키워드 폴백 순위 재사용 / 별도 엔진)
4. **재순위 모델** — 후보 20개를 다시 줄 세운다. P@5를 겨냥한다. 자체 호스팅 가능한 다국어 재순위 모델로
5. **LLM 질의 재작성** — 의미형("크레인에서 기름 새")을 용어형으로. D4에서 이미 쓰고 있으면 확장
6. **임베딩 모델 교체·파인튜닝** — 실사용 질문과 정답이 쌓인 뒤. 그 전에는 합성 문장 틀만 외운다

### 3단계 — 기업 운영 요건 (C2·C4·C6)

| 항목 | 내용 |
|---|---|
| 자체 호스팅 운영 | 1단계 비교 결과로 모델 확정. vLLM 등 서빙 엔진, GPU 대수(동시 사용자 기준), 장애 시 동작(검색 결과만 보여 주기) |
| 데이터 범위 확장 | 규정 문서(pylab regdocs: 법제처 조문 → `SourceType.REGULATION`, `PUBLIC`, 시행일 필터). 사내 작업 표준서는 문서 꼴을 보고 그때 |
| 감사 기록 | `chat_history`에 이미 질문·답·근거가 남는다. 보존 기간(SLO 9-2, 90일 후보)과 조회 권한을 정한다 |
| 비용 상한 | 사용자별 한도(`ai.quota.daily.chatbot=20`)는 있다. 전체 일일 상한과 넘었을 때의 동작을 정한다 |
| 품질 모니터링 | 답에 "도움이 됐나" 피드백, `retrieval_mode=KEYWORD` 비율(SLO 3-5), 근거 없음 비율의 일일 추이 |
| 근거 없음 판정 | 신호(AUROC 0.64)가 약하다. 재순위 점수나 LLM 자체 판정으로 다시 잰다. 3절 "답 없음 처리"의 수단 |

## 7. 1단계 결과 (2026-11-26) — 병목은 생성이 아니라 검색이다

원 출력과 전체 표는 `measure/rag-e2e/2026-11-26/summary.md`(PR #204). 판정기(qwen2.5:14b) 값이라 사람 재채점 전까지 `[미검증]`.

| 검색 결과 | gpt-4o-mini | qwen2.5:7b | exaone3.5:7.8b |
|---|---|---|---|
| 정답을 찾음 — 충실도 / 거부 | **1.00 / 0.00** | 0.96 / 0.09 | 0.96 / 0.02 |
| 못 찾음 — 충실도 / 거부 | 0.72 / 0.56 | 0.66 / 0.61 | 0.69 / 0.32 |

- **정답 근거가 들어가면 C1(충실도 ≥ 0.95)은 자체 호스팅 7~8B로도 지켜진다.** 운영 모델 후보가 7~8B여도 된다는 첫 근거다.
- **목표 미달은 검색이 틀렸을 때 나온다.** `min-score=0.0`이라 엉뚱한 근거 5개로 답을 짓는다(#203). 그래서 **2단계(검색)를 바꾸지 않는다** — 순서가 맞다.
- **답 없는 질문**(코퍼스에 없는 내용)은 세 모델 모두 거의 전부 "찾지 못했다"고 답했다(0.83~1.00). 단 근거가 빈 경로(#197의 본 대상)는 재지 않았다.
- **후속 질문**(#198): 앞 질문 없이 0.00 → 붙여서 ko 0.67~0.70, vi 0.50~0.53, en 0.17~0.20. LLM 질의 재작성은 급하지 않다(D4).
- **D2 재평가:** 자체 호스팅은 품질은 근접하지만 **응답 시간이 목표를 못 지킨다**(T4, p95 10~39초, #202). C4로 자체 호스팅이 필요하다면 3단계의 서빙 엔진·GPU 결정이 품질보다 먼저다.
- 새로 드러난 것: 작은 모델이 `<자료>` 태그를 답에 옮겨 적는다(#201).

### 1단계 뒤 남은 것

1. 사람 재채점(`human_check.tsv`, 언어별 10건) — 판정기 값을 믿을 수 있는지
2. 안전 질문을 평가셋에 넣기 — 3절 "안전 질문 충실도 0건"을 아직 못 쟀다
3. 일반 근로자 경로(근거가 비는 경우)로 같은 측정

## 5. 하지 않는 것

- **LLM 파인튜닝.** 지식은 RAG가 넣는다. 지금 약한 곳은 검색이라 LLM을 학습시켜도 답이 맞지 않는다. 말투·형식 문제가 남으면 그때 본다.
